# Negative tests that are finished and whose assertions `make test` should run.
#
# One name per line, no .c extension. Blank lines and #-comments are ignored.
#
# Same mechanism as c-drills/DONE.txt and for the same reason: an unwritten
# test still has to COMPILE, so a syntax error turns the badge red the day it
# is committed, but it is not executed and it is not claimed. A suite that ran
# three skeletons and printed three lines of "not implemented" would be a green
# CI job asserting nothing, which is worse than a red one.
#
# Add a name here only when the test:
#   1. asserts the five (or four) cases its header comment lists,
#   2. asserts them by STATUS CODE and not by message text (rule 16),
#   3. has been run against the deliberately wrong implementation its header
#      names, and caught it (rule 11),
#   4. is clean under -Werror, AddressSanitizer and UndefinedBehaviorSanitizer.
#
# W11 wrote all three. Condition 3 is no longer a thing a person does once and
# remembers: each file declares its own defect variants and exactly which cases
# each must move, `make test` builds and runs every one of them, and a defect
# that moves a case nobody predicted fails the build the same way a defect that
# moves nothing does.
#
#   test_offset_length         9 cases, 8 defects
#   test_oversized_field       7 cases, 6 defects, plus the two --asan-demo runs
#   test_transcript_coverage   8 cases, 6 defects, plus a calibration
